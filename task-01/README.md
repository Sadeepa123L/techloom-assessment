# Techloom Assessment - Task 01: POS Order & Inventory System

## 📌 Project Overview
This project is a Concurrency-Safe Point-of-Sale (POS) backend and frontend. It handles product inventory management, order creation under concurrent load, prevents overselling, and gracefully handles payment outcomes (Success, Failed, Timeout).

## 🏗️ Architecture & Tech Stack
- **Frontend:** React.js, TypeScript, Vite
- **Backend:** Java, Spring Boot, Spring Data JPA
- **Database:** MySQL
- **Containerization:** Docker (Multi-stage build for backend)
- **Concurrency Strategy:** Database-level Pessimistic Write Locks (`@Lock(LockModeType.PESSIMISTIC_WRITE)`) are used to prevent overselling when multiple cashiers check out the same product simultaneously.

## 🚀 Setup Steps (Local Development)

### 1. Database Setup
Ensure you have a MySQL server running. Create a database named `defaultdb` (or as configured in your properties/URL). The tables will be auto-generated by Spring Boot (Hibernate).

### 2. Backend Setup
1. Navigate to the backend directory: `cd task-01/backend`
2. Ensure the `.env` file is created.
3. Run the Spring Boot application using Maven:
   - On Windows: `mvnw.cmd spring-boot:run`
   - On Mac/Linux: `./mvnw spring-boot:run`
4. The backend will start on `http://localhost:8080`.

### 3. Frontend Setup
1. Navigate to the frontend directory: `cd task-01/frontend`
2. Install dependencies: `npm install`
3. Ensure the `.env` file is created.
4. Start the development server: `npm run dev`
5. The frontend will be accessible at `http://localhost:5173`.

## 🧪 How to Test Each Feature

1. **Product & Inventory Management**
   - Navigate to the **"Manage Products"** tab.
   - Use the UI to Create, Read, Update, and Delete products. Check that the available stock count updates correctly.

2. **Cart & Order Creation**
   - Navigate to the **"POS Checkout"** tab.
   - Add items to the cart. If you try to add more items than the available stock, the UI will prevent it.
   - Click "Checkout" to place the order. 

3. **Concurrency & Overselling Prevention**
   - The backend uses pessimistic locking. If multiple users attempt to checkout the last remaining stock of a product exactly at the same millisecond, the database lock ensures only one transaction succeeds, and the other will fail safely, preventing overselling.

4. **Stock Reservation & Expiry**
   - When you click "Checkout", the stock is immediately moved to "Reserved" in the database.
   - Wait for 5 minutes without completing the payment. A background scheduled job will mark the order as `EXPIRED` and release the stock back to the available pool.

5. **Mock Payment Handling**
   - After clicking "Checkout", a payment modal appears.
   - **Simulate Success:** Marks the order as `PAID` and permanently deducts the reserved stock.
   - **Simulate Failed:** Marks the order as `FAILED` and restores the reserved stock back to available inventory.
   - **Simulate Timeout:** Marks the order as `EXPIRED` and restores the stock.

6. **Order History**
   - Navigate to the **"Orders"** tab.
   - You can view a complete history of all orders with their respective statuses (RESERVED, PAID, FAILED, EXPIRED, CANCELLED) and total amounts.
